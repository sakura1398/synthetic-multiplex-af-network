# Dataset card

## Dataset name

Synthetic Multiplex Atrial Mapping Dataset

## Short description

This dataset is a synthetic, two-dimensional atrial mapping dataset created for methodological investigation in a Network Science project. It was designed to support the study of sequential local observations under spontaneous and paced conditions, with known hidden substrate structure.

The dataset is not a clinical atrial fibrillation dataset. Its purpose is to provide a controlled environment in which hidden structural components are known and node-role metrics can be evaluated against synthetic ground truth.

---

## Motivation

The project investigates how sequential local observations can be integrated into a multiplex network representation of a larger hidden substrate.

A clinical dataset was not used because the goal of the project is methodological rather than clinical. A synthetic dataset provides several advantages:

- the hidden substrate is known,
- the observation process can be controlled,
- feature generation rules are explicit,
- the relationship between observations and hidden structure can be inspected directly,
- null models and sensitivity analyses can be interpreted more clearly.

This dataset was therefore created to test whether stable, condition-dependent, and bridge-like node roles can be identified from sequential spontaneous and paced observations.

---

## Intended use

This dataset is intended for:

- methodological testing of multiplex network construction,
- node-role analysis under known synthetic ground truth,
- controlled experiments on sequential patch observations,
- sensitivity and null-model analysis,
- demonstration of a local-to-global synthetic mapping framework.

This dataset is **not** intended for:

- clinical diagnosis,
- treatment planning,
- patient stratification,
- real atrial fibrillation interpretation,
- direct clinical validation.

---

## Domain and geometry

The dataset represents an abstract two-dimensional atrial-like surface.

- Domain size: **100 mm × 80 mm**
- Observation patch: **4 × 4 electrodes**
- Electrode spacing: **4 mm**
- Patch movement: sequential placements across the domain
- Time step between placements: **25 minutes**

The patch is treated as a local sensing window moving across a larger hidden system.

---

## Hidden substrate structure

The hidden substrate contains five latent components:

1. **Source region 1**
2. **Source region 2**
3. **Block region**
4. **Low-voltage region**
5. **Vulnerability region**

These regions are not observed directly by the network analysis. Instead, they influence the generated electrode-level and patch-level features.

This allows the dataset to function as a controlled synthetic environment with hidden structure that can be used for evaluation.

---

## Observation conditions

Two observation conditions are generated for each patch placement:

### 1. Spontaneous condition
This condition represents naturally emerging activity driven by the hidden sources and substrate interactions.

### 2. Paced condition
This condition represents a controlled perturbation in which activation is driven from a fixed pacing site.

The paced condition is important because it acts as a probe: it may reveal hidden conduction abnormalities that are less visible under spontaneous activity alone.

---

## Main generated quantities

The dataset includes electrode-level and placement-level information.

### Electrode-level generated quantities
Depending on the script stage, the dataset may include synthetic variables such as:

- local activation time (LAT),
- amplitude / voltage proxy,
- fractionation index (FI),
- local field-related quantities,
- waveform timing or morphology descriptors.

### Placement-level generated quantities
These are later aggregated into patch-level or node-level descriptors, including:

- spontaneous importance score,
- paced importance score,
- dispersion or heterogeneity summaries,
- discordance-related quantities,
- bridge-related quantities.

## Main files generated by the project

The exact generated files depend on which stage of the pipeline is executed.

### Core forward-model outputs
Produced mainly by `code13.py`:

- `spontaneous_electrode_features.csv`
- `paced_electrode_features.csv`
- `placement_table.csv`

### Waveform-related outputs
Produced mainly by `code15.py`:

- synthetic unipolar waveform tables
- synthetic bipolar waveform tables
- waveform metadata tables
- selected waveform figures

### Network-analysis outputs
Produced mainly by `CodeB1.py`, `CodeB2.py`, `CodeB25.py`, `CodeB26.py`, and `CodeB3.py`:

- node tables,
- adjacency matrices,
- node-role summary tables,
- null-model summaries,
- sensitivity summaries,
- figure outputs for network interpretation.

Only representative outputs are stored in the repository.

---

## Data generation process

The dataset is generated in a staged pipeline:

1. define the hidden substrate,
2. define the sequential patch trajectory,
3. generate spontaneous and paced electrode-level observations,
4. aggregate local observations into placement-level descriptors,
5. convert placements into a multiplex network,
6. compute node-role metrics,
7. evaluate sensitivity and robustness.

This staged generation process is important because the dataset is not a static table; it is the product of a controlled synthetic observation model.

---

## Reproducibility

The dataset generation process is designed to be reproducible.

- fixed random seeds are used,
- code order is documented,
- the main reproducible pipeline is described in `docs/code_order.md`,
- the repository includes the scripts used to regenerate the main outputs.

Examples of fixed seeds used in the project include substrate generation, trajectory generation, and feature-generation seeds.

---

## Strengths of the dataset

This synthetic dataset has several methodological strengths:

- hidden structure is known,
- ground truth is available in principle,
- spontaneous and paced conditions are both available,
- the observation process is sequential rather than static,
- the dataset supports multiplex interpretation,
- the dataset allows controlled testing of node-role metrics,
- the dataset is reproducible.

---

## Limitations of the dataset

The dataset also has important limitations:

- it is synthetic rather than clinical,
- the substrate exists in an abstract 2D domain,
- the waveform generation is illustrative rather than biophysically complete,
- the mapping process is simplified relative to real atrial electrophysiology,
- the dataset does not capture full anatomical complexity,
- node-role success on this dataset does not guarantee clinical validity.

These limitations are essential to the interpretation of the project and should be kept explicit.
